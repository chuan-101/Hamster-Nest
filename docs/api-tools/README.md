# API 会话工具与费用

App 的 API 私聊现可按会话选择 27 项时间轴、Memo、待办、AAB 工具。默认不开放工具；设置在云端保存。CLI、群聊和定时任务的路由不变。

## 使用

在 API 聊天页底部打开「工具与费用」，展开时间轴 / Memo / 待办 / AAB，逐项或按读取、写入组选择，再保存。每条回复显示本轮调用次数、上游费用及工具状态；面板显示本会话、北京时间今日全部 API 私聊的累计用量。统计从这次功能上线开始，包含测试和归档会话，不包含 CLI、旧调用、充值手续费及税费。没有收到金额的请求显示「费用待核对」。

## 执行与恢复

- `conversation-dispatch` 继续先验证当前用户与 owner，再准备原有 canonical 消息；`mode=api_tools` 提供设置和统计。
- 工具定义和服务器说明来自两个现有 MCP 的 initialize / tools/list；发送给模型的定义只包含所选白名单，执行前再次检查云端权限。已发出的操作无法撤回。
- 后端流式模型循环最多 6 次请求、12 次工具调用、125 秒，手机断开不撤销已接受的后台工作。最终回复、工具状态、费用均落库，App Realtime 加轮询对账。
- 模型循环使用 dispatch 已按 recipe / token budget 选出的 canonical 上下文；不再把 conversationId 交给旧代理的历史重建压缩，以免丢失本轮 tool / reasoning 消息。已有身份、风格、历史选择、时间选项不变。`reasoning_details` 保留在本轮工具往返中，不展示或持久化为用户消息。
- `api_tool_executions` 在调用前写入唯一 reply + 参数指纹。成功和失败回执可重用；网络超时、崩溃窗口中不确定的写入不自动重放。重试时已有写入尝试则阻止换参数再次写入，要求先读取核对或在新消息明确补做。
- `api_model_calls` 在请求前记录 pending，逐次保存实际 usage；失败、断流也记账。缺失上游金额不能还原真实扣费，留作待核对。旧 `llm_usage` 继续逐次记录。
- 三张新表 RLS 仅允许 owner 读取，客户端不能直接写入；设置和执行账本只能由已验权后端写。汇总函数为 SECURITY INVOKER。
- 时间轴 `source=api, recorder=syzygy`；迁移补齐 MCP 已有但数据库缺失的 api 来源。AAB 旁批/导读按实际模型署名，问答现有枚举仅支持 Claude/GPT，其他模型禁止冒用署名。

## 验证（2026-11-05）

- 单元/数据库测试覆盖碎片 SSE、reasoning 回传、权限撤回、重复写入、未知结果、防跨用户读取、未知费用、模型工具循环和断开客户端。
- UI 用真实 React Native Web 组件及模拟数据，检查默认 / 地质主题、390px 布局、分组展开及保存。并非真机验收。
- 线上 Opus 5.5：时间轴+AAB读取；AAB临时导读写入并删除；修复来源约束后时间轴写入并删除。重放相同 clientId 不新增模型调用。8 次模型调用，合计 $0.1006422，全部收到费用。两条测试会话归档，临时认证会话退出。
- 首轮时间轴写入曾因旧 source CHECK 失败，已通过 `timeline_api_source` 修复并单独重测成功；失败调用也计入上述费用。

## 发布与回滚

后端部署 `conversation-dispatch`，应用两份同日迁移并同步生成类型。回滚后端可从基线 `0a0e06b` 部署原 conversation-dispatch（包含该目录依赖）；新增表保留即可，不删除用户设置或账本。App 只增加 JS/TS UI，不变更原生模块或权限，目标为 production / iOS runtime 1.0.7，兼容 1.0.7(25)。回滚 App 可回到该 runtime 的 embedded update；旧 1.0.5 OTA 不是同 runtime 回滚目标。

真机待用户确认：更新下载与重启、两个主题、工具选择保存、实际陪伴中的时间轴/AAB操作、锁屏/断网恢复和费用显示。

## 核心工具扩展与旧版兼容（2026-11-05）

新增 Memo 列表、标签列表、新增、修改，以及待办列表、新增、完成，共 7 项。沿用同一执行账本和每会话权限，未自动开启新工具；不提供删除。Memo 新建来源强制为 api，待办创建者强制为 syzygy。现有 schema 可直接承载，无新增迁移。

设置接口 catalog_version=2 返回全部 27 项；未声明版本的旧 App 继续收到原来的 20 项及对应选择。旧 App 保存时保留其无法展示的 Memo/待办权限，新 App 可以明确撤销全部权限。模型执行始终依据完整云端权限。

验证：275 项测试、Deno 类型检查、backend check 通过（既有 5 条警告）；新增测试覆盖混合客户端保存、正确 MCP 路由、撤权、防重放和写入来源。

线上 Opus 5.5 验收覆盖全部 7 个新增工具：Memo/标签/待办读取、Memo/待办新增、Memo 修改、待办完成；数据库回读确认来源与最终状态。两条请求重放均未再执行，临时 Memo、待办及测试分类清理，会话归档并撤销测试权限。共 5 次模型调用，实际费用 $0.1235308。旧版目录仍为 20 项，旧版保存不会清除新工具权限，v2 能清空全部选择。
